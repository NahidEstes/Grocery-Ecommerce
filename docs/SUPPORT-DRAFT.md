# Support and updates — seller draft

Status: proposal only. Do not advertise an SLA or included support period until the seller completes these decisions.

- Seller support address/channel: **[decide]**. Business hours/timezone and expected response time: **[decide]**.
- Included support duration after purchase: **[decide]**. Update entitlement/duration and delivery channel: **[decide]**.
- Proposed included scope: reproducible defects in the unmodified documented starter on supported Node versions, setup questions answered by the supplied docs, and announced security fixes during the agreed entitlement period.
- Proposed paid/separate scope: custom features/design, data migration, gateway/provider approval, hosting/server operation, private integrations, production incident response, content entry and third-party policy changes.
- Version compatibility, breaking-change/migration policy, refund/remedy terms and end-of-support notice period: **[decide]**.

Ask buyers to provide version, OS/Node version, redacted error, reproduction steps and expected/actual behavior. Never request passwords, `.env`, merchant secrets, reset links, private order receipts or an unredacted customer database. Use test data and a temporary staging environment for reproductions.

Updates should include a changelog, backup instructions, migration steps when needed, dependency/license inventory changes and the verification boundary. Test against a fresh copy and merchant staging before applying updates to a live store. No automatic update or hosted support service is bundled.
